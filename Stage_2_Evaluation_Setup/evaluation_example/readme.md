# STT Evaluation Setup

## Overview
This project provides a standardized process for evaluating Speech-to-Text (STT) systems using an in-house Word Error Rate (WER) evaluation tool.

The goal is to produce **consistent**, **transparent**, and **linguistically meaningful** accuracy results.  
Although the provided example uses **English**, the WER tool can be used with **any language**.

You can run the example in two ways:
- Using the bash script: `main.sh`
- Using the Jupyter notebook: `wer_evaluation.ipynb`

---

## Evaluation Command
The evaluation is performed using the following command:

```bash
python wer.py <gt_file> <predict_file> allowed_replacements.txt allowed_insertions.txt allowed_deletions.txt out_stat_file
```

---

## Input Files

- **`<gt_file>`**  
  Ground truth transcription created and validated by a language expert.  
  The text must be normalized:
  - lowercase
  - no punctuation
  - no pronunciation hints

- **`<predict_file>`**  
  Transcription generated by the STT system being evaluated.

- **`allowed_replacements.txt`**  
  List of allowed semantic substitutions (e.g. `doctor ↔ dr`).

- **`allowed_insertions.txt`**  
  List of allowed filler words that may appear in STT output (e.g. `uh`, `hum`).

- **`allowed_deletions.txt`**  
  List of allowed filler words that may appear in the ground truth (e.g. `uh`, `hum`, `you know`).

- **`out_stat_file`**  
  Output file containing evaluation statistics and error details.

---

## Output Statistics
The output file includes aggregated metrics and detailed error analysis.

Example:
```
M = 2765, S = 81, I = 17, D = 30
WER = 4.5%, recall = 96.1%, precision = 96.6%, F1-score = 96.4%
```

---

## Metrics Definition

- **Word Error Rate (WER)**  
  `(S + I + D) / (M + S + D)`

- **Recall**  
  `M / (M + S + D)`

- **Precision**  
  `M / (M + S + I)`

- **F1-score**  
  `2 × Precision × Recall / (Precision + Recall)`

These metrics together provide a balanced view of recognition accuracy and error behavior.

---

## Error Breakdown

- **Substitutions (S)**  
  Reference words replaced by incorrect words in the STT output.

- **Insertions (I)**  
  Extra words added by the STT system.

- **Deletions (D)**  
  Reference words omitted by the STT system.

Each error type is reported with occurrence counts for detailed analysis.

---

## Allowed Error Files
Allowed error files are used to prevent non-semantic differences from negatively affecting WER:

- **Allowed Replacements**  
  Semantically equivalent words or expressions.

- **Allowed Insertions**  
  Filler words that may appear in STT output.

- **Allowed Deletions**  
  Filler words that may appear in ground truth.

---

## Benchmarking Workflow

1. Audio data is manually transcribed by a language expert to create ground truth.
2. The STT system generates predicted transcriptions.
3. The WER tool compares ground truth and predicted text.
4. Evaluation statistics are reviewed and analyzed.

---

## Iterative Evaluation Policy

Before the first benchmark run, all allowed error files are empty.  
After each benchmark, a language expert reviews the results and updates the allowed error files as needed.

In this example, some allowed entries were intentionally removed. You should add the relevant allowed examples again and observe how the WER changes.

---

## Notes
This evaluation setup ensures a fair comparison between STT systems and aligns quantitative metrics with real-world linguistic relevance.
